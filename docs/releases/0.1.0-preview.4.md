# UnlimitedClipper 0.1.0-preview.4

A small Windows preview update for the processing-history layout.

- Titles, meters, and percentages align across every job status. Empty action slots no longer
  change the progress width or starting position. Narrow screens retain a stacked layout.
- Retry and cancellation use small icons with translated tooltips and accessible names.
  Their 44-pixel hit areas remain keyboard-operable and disable during pending requests.
- Windows tool setup uses ZIP entry streams with nested-file overwrite and destination checks,
  fixing the archive-module failure on the ARM64 GitHub runner.

Choose **arm64-setup.exe** for Snapdragon/ARM Windows PCs, or **x64-setup.exe** for Intel/AMD PCs.
Install for the current user. Models remain separate from the application; choose/download them
in Settings after a fresh installation. SHA256SUMS covers the attached installers and updater files.

Frontend checks and the expanded browser layout scenario passed, including 390/1280/1920/2560
pixel widths, mixed job statuses, keyboard retry, pending state, and an actual MP4 preview.
The live Windows ARM64 host separately verified all 26 real processing rows without JavaScript
errors or misaligned meters. This change does not modify the clipping engine.

Hosted quality checks passed on Windows, Linux, macOS Intel, and Apple Silicon. The Windows
ARM64 media workflow passed editorial/scene rendering and all eight browser tests. Source checks
are distinct from packaged installer/runtime certification.

This remains an experimental side project. Captions and automatic moment selection need human
review. Installer install/uninstall, updater installation, and physical x64 runtime remain
untested. Android runtime is untested; Linux/macOS packages are outside this Windows preview.

Updater artifacts use version-bound publisher signatures. Windows Authenticode signing is not
configured, so an unknown-publisher prompt is possible. The repository and preview downloads are
public. Automatic installation still requires a configured publisher update feed. Local and hosted
verification are recorded in docs/validation.md. Keep a backup when trying preview builds.
